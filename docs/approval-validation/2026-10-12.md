# Codex approval cards — local validation

The feature is based on desktop Yukio 0.4.3 source revision `e888c26ccdd7db7f87fd497490bb796ceeae76d0`. The older handoff checkout was used for initial investigation only; this branch retains 0.4.3's updater, chat visibility behavior and installed animation assets.

## Behavior

Local Codex command execution, file change and permissions requests enter the existing question-card router. Users explicitly choose approve once or decline. Closing the card dismisses the reminder without replying. Approval cards have no free-text submission or default selection. Permissions grants use turn scope, never permanent/session-wide approval.

The sender fetches the current snapshot and verifies the conversation, current turn, typed request ID and full request contents. Resolved, changed, duplicate and wrong-thread requests cannot be submitted. A successful IPC acknowledgement alone does not dismiss the card: the pending request must disappear from a subsequent snapshot. A stale user-input receipt with the same ID does not count as approval confirmation. Request reads and sends run off the UI thread; delayed reads retain their start timestamps so the router can reject events from an older task.

## Evidence

- macOS: full Swift suite, 207 tests passed; subsequent approval/background-answer regression run, 14 passed.
- Python: full suite, 271 tests run, 270 passed and one Windows-only named-pipe test skipped on macOS; subsequent Codex regression run, 29 tests run with the same Windows-only skip.
- Transport fixture exercised approval acknowledgement, confirmed removal and acknowledgement without removal using a real local byte-stream socket. No live conversation was approved by the test.
- Native AppKit approval-card render inspected: operation description, approve/decline options, close and open-chat controls visible; free-text field absent. Hit tests cover the controls and router transition back after resolution.
- Read-only connection to the running Codex desktop succeeded. Its canonical history uses `turnId`, which the adapter accepts; the legacy `id` shape is also supported.
- Source animation assets match every corresponding installed desktop asset by SHA-256. No animation source or generated resource was modified by this branch.

## Limits

This is a local development delivery, not a GitHub release. Windows implementation and cross-platform logic are included; Windows native UI/pipe execution and a Windows installer have not been verified here. There was no real pending approval available for a live end-to-end decision. Claude Code and Deep Code authorization remain in their original permission interfaces; their question-answer adapters are not approval transports.
