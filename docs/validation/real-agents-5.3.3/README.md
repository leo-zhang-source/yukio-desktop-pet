## 已发现的问题

宿主机对原 5.3.2 安装包的 `spctl --assess --type execute` 返回拒绝。候选仍为临时签名、未公证；本机没有有效 Developer ID 签名身份。签名完整性通过不等于普通用户下载后能直接打开。

本轮客体使用的公开系统镜像原先关闭了 Gatekeeper；验收前已重新开启，并核对 `assessments enabled`。重新开启后的应用来源限制为“App Store”，这比常见的“App Store 与被认可开发者”更严格，不能称为已验证普通默认设置。

通过客体 Safari 实际下载 ZIP，保留 Safari 设置的 `com.apple.quarantine`，由系统解压后复制到 `/Applications/Yukio.app`。客体安装的全部 472 个文件与候选包逐一核对一致，代码签名完整性通过。通过正常系统启动路径首次打开时，macOS 明确阻止运行；客体独立安全评估也返回拒绝。已找到系统“Open Anyway”入口，正在等待用户对仅此测试包的单次放行确认。尚未建立例外，没有删除隔离属性，没有关闭安全检查来运行应用。

两家官方客户端随后在客体从官方 HTTPS 下载地址安装，文件摘要与官方发布元数据一致，代码签名检查通过；实际版本为 Codex CLI 0.165.0、Claude Code 2.1.308。首次账号检查分别返回未登录、`loggedIn: false`，未沿用开发者账号。
