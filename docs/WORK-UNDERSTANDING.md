# 工作台：正在发生与工作解读

2026-10-29，Mac 开发候选。此次根据用户要求重组工作台，并参考既有调查；不是公开发行，也没有替换桌面正在运行的 App。Windows 按用户决定暂缓。

## 页面与用户流程

现有内容、解释、原因、深入解释、历史和交接依据统一归入“正在发生”。默认只展示最近可见活动及其状态；其余过程在同一类中展开。结束、取消与整项工作验收保持不同含义。

新增“这项工作如何推进”，可以在“这次聊天”和“整个项目”之间切换，按三个问题阅读：

1. **要达成什么目标**：保留较早明确要求与最近补充，讲清问题、希望得到的结果，以及记录中明确提出的完成条件。
2. **用什么方法与策略**：联系目标解释公开提出的做法、理由、前提和取舍，区分计划与已执行步骤。
3. **方法是否有效**：把已知结果与目标对照，说明支持到哪里、哪些仍待验证、需要哪类后续检查。操作成功、助手自述、轮次结束和操作数量都不能独自证明方法有效；不提供没有依据的评分或百分比。

打开页面与切换范围只整理本机摘要。启用自己的解释服务后，点击“解读这次聊天”或“解读整个项目”生成连贯解读；项目解读按次触发，不继承当前聊天的自动发送范围。首次未配置、登录失效、模型不可用或调用失败时，本机摘要与依据仍可查看。

## 上下文与证据边界

- 聊天摘要使用当前已校验来源中开场与近期的少量公开摘录，保留明确方法与结果汇报，不读取内部思考。原来的有限读取窗口继续生效，不声称读取了完整聊天。
- 项目按当前客户端给出的项目身份或工作目录身份匹配，不按名称合并；不跨客户端猜测同一项目。此次也统一了 Codex 聊天详情与侧栏的项目身份读取。
- 每次最多纳入六段聊天，包括当前聊天与最近可读的同项目聊天；侧栏自身也有最近记录窗口。页面直接显示实际采用数量和不完整性，展开可看来源列表。这个选择入口表示项目视角，不代表全部历史已覆盖。
- 每条操作和结果仍在原聊天内配对；同属项目不证明共同目标、依赖关系或因果。项目归属变化、聊天切换、关闭页面时，过期返回不能写进新范围；发送前再次确认页面授权仍有效。
- 每段解读保留自己的引用。目标引用要求，方法引用公开方案，有效性引用结果与限制；项目范围对纳入的每段聊天保留引用要求。引用存在、格式正确不等于语义已核实，模型仍可能出错。
- 已有解读绑定它自己的资料版本与来源；记录变化时标为较早解读。纯操作记账变化不强制把解读标旧。失败时保留已有内容，不伪造模型结果，也不把无结果说成失败。
- 新模块已进入便携源码包清单与运行代码指纹。包不包含本次测试记录、个人聊天、账号设置或凭据。
