## 已核实的边界与原因

Claude 转录适配器本身独立实现，并非直接使用 Codex 记录格式。但工作台原先只有 Codex 式等待标记，未从 Claude 的未结束 AskUserQuestion 恢复等待；角色、工作台、回答通道和桌面聊天回退身份之间也缺少完整衔接。

- 转录的单个模型回复结束、工具结果、客户端一轮结束是不同事实。未结束工具／问题必须按调用身份保留；并行结果的时间戳可能比后写入的请求更早，不能只用会话级时间水位丢弃。
- 同一 AskUserQuestion 包含多题，转录调用与回答通道中的逐题请求需要关联。逐题切换不能先显示思考；原聊天回答也必须撤掉该调用的通道卡。通道结束晚于完成记录时，不能丢掉已确认的结束。
- 实际 66 版独立 VM：双题等待期间，工作台未提示回答；等待约 570 秒后，PreToolUse 回退至 PermissionRequest，雪绪把 AskUserQuestion 误显示为工具允许／拒绝。原 Claude 仍显示颜色／形状问题。随后在原聊天回答 Red／Circle，实际正常完成。该证据证明通道分类问题，不单独证明用户所有闪退均由这一处造成。
- Claude Desktop 回退会产生新的 CLI 转录并复制旧历史；必须按明确 current/prior 关系排除旧分支，不能把旧文件再次改动当作另一个实时聊天。
- Claude 近期客户端提供独立进程登记，实际观察到 `busy`、`waiting`、`idle`。只读取数字 PID 命名的 JSON，核对 PID、进程启动身份、当前用户与会话；不读 peer key 或 socket。不把 `idle` 或进程退出当作成功完成。未知格式保守回退。
- 已安装回答助手是独立副本；替换主 App 后，必须检查已有通道是否仍运行旧助手。
- 真实 VM 的拒绝授权回执为 `is_error: true` 加 `Permission denied by hook`。旧实现把用户拒绝显示为工具故障；现在保留原始错误标记，但把操作结果归为取消，不能宣称文件已写入。
- 工作台原先优先显示上一条公开进展；即使已有等待状态，当前问题仍可能埋在工具记录中。现在按未结束调用身份查回原始问题并核验原文件，显示当前未回答题目；大量过程记录不能挤掉问题，逐题回执会推进内容。问题文字只在本地按需读取，不写入状态保存点。
- 回答通道的逐题回执先于转录结果时，已答问题不得重新闪出。PermissionRequest 没有调用编号时，只接受原转录里名称与输入完全一致且唯一的未结束调用；不按名称、时间接近或聊天标题猜测。570 秒换通道后，只在同一聊天、同一调用、同样题目下继承已有题目回执，不继承批准操作。

## Codex 追加排查与合并候选 68

用户明确指出“有问题不显示”。实际本机记录证实：`request_user_input_async` 返回 `accepted: true` 后，助手可以结束当前回合，而问题仍可在下一回合收到带调用编号与题号的回答。已回答的两条历史授权问题及本次症状选择均符合此结构。仅核对结构和时间关系，不提交真实问题、回答、账号资料或客户端提取代码。

已处理的具体原因：

- 原生路由把所有问题视为当前回合中的阻塞工具，结束、新回合、普通用户消息会清掉尚未回答的异步问题。现在异步问题独立保存，仅对应题目的回执或明确失败撤销该题；`accepted` 只是受理，不是回答。
- 一次多题原来只读第一题，且第 0 题回答会关闭整次调用。现在按调用编号与题号逐题处理；重复记录、其他问题的回答、旧回合回执不能相互覆盖。
- 工作台状态保存点没有异步待答集合，元数据又去掉了题号及回答关联。现在保存无正文的待答身份，支持跨批次、重启、回合结束、压缩及大量噪声；旧数据库保留原代，按新版读取模型回读原文件。
- 原生启动只看末尾 1 MiB，较早的待答问题无法恢复。现在对追踪文件分批补读，每轮上限 4 MiB，只在追至文件末尾后恢复仍未回答的问题，不回放历史工作状态。子任务的明确历史序号边界先于继承的头部与内容生效，避免把主聊天的问题算到子任务。替换、截断与删除区分具体来源；一个分页文件消失不会清空同聊天仍存在的来源。
- 工作台读到一半时曾直接显示历史状态，可能先出现旧问题或完成，下一批才撤掉。现在明确显示正在读取最新记录；读完后才呈现当前状态。有积压且确有进展时继续公平分批读取，不在每批之间额外停等两秒；无进展、缺失来源或错误保留原等待与退避。
- 后台回答原来只认当前进行中的回合和第一个问题。现在先读取该聊天完整的规范历史，核对准确题目、选项、题号及全部后续回答；仍工作时发送中途回答，已结束时按客户端原有流程开始回合并继承聊天设置。当前客户端结构来自本机官方 App 的只读静态核对；真实客户端送达仍待 VM 验收，模拟通信通过不等于真实送达通过。
- 阻塞式 `request_user_input` 的多题请求仍需回原聊天一起回答。它保持可见并明确提示后台回答不支持，不再错误提示问题过期。Codex 界面的本地“跳过”偏好未写入转录，不宣称能从日志读取该偏好。

本机定向结果：原生 Codex／回答通道 57 项、工作台全套 398 项通过（增加积压子进程检查前）；新增真实记录子进程检查在 3 秒运行窗口内读完 1,504 条样例并确认两题已答。正式冻结后的两遍检查、实际包脱离开发环境检查和独立真实矩阵尚待完成。
