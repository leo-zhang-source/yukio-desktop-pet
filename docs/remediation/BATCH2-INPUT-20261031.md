## YK-03：复现并修复发送失败后的编辑焦点丢失

在使用生产 `QuestionPanel` 的本机原生诊断窗口中，用人工草稿测试：发送中禁用文本框，模拟失败后 `enabled=true`，但 `first_responder_is_editor=false`。直接键入 `abc` 没有新增文字，重新点击输入框才恢复。这是已复现的具体故障路径；尚不能断言用户之前所有“有时不能输入”都由它造成。

原因是 AppKit 禁用文本框时结束了编辑，而重新启用不会自动恢复编辑器。已有草稿保留代码保存了文字，却没有保存及恢复编辑焦点和插入位置。

本批在禁用时记录原本属于该输入框的选区。失败后只有窗口仍可见、仍为 key、问题未切换且焦点未交给另一编辑器时，才恢复原编辑器与选区；不调用 App 激活，也不强制成为 key。换题或清空时废弃旧恢复信息，后台窗口不抢焦点。选区按 UTF-16 长度限界，保留末尾插入点，避免恢复后从头插入或覆盖整段草稿。

修复前新增回归失败，修复后通过。一次中间实现的空选区交集返回起点，导致续写位置错误，已由测试发现并改为限界位置；失败日志保留，未放宽断言。

## YK-10：已有修复的实际验证

第一轮实现的规则保持不变：选词期间 Escape／Return 交给输入法，普通 Escape 收起并保存草稿，重新打开仍可继续编辑，成功发送才清空对应草稿。本批补充证据，而非重复宣称重新实现。

- 本机诊断窗口连续 **10 次**“模拟发送中 → 失败 → 不再点击输入框直接续写”，十次均恢复焦点，字符依次附加在草稿末尾；日志中的十条 `send_failed` 均 `first_responder_is_editor=true`，修复前对应值为 false。
- 使用现有 Apple 简体拼音 `com.apple.inputmethod.SCIM.ITABC`，通过实际 n/i/h/a/o 按键进入选词，不以粘贴充当输入法操作。**5 次**选词中刷新、Escape 取消，已提交文字均保留；Return 结束组合没有触发发送，Space 提交“你好”后 Escape 收起重开保留完整中文草稿。过程中诊断记录观测到 marked text，最终模拟回答计数为 0。
- 新增生产 `AppController` 的隔离回归：Escape 关闭重开保存精确草稿及多选项，A／B 两聊天各切换 **10 次**，草稿不混用，隐藏角色后恢复草稿。此入口仅 DEBUG 编译，不进入正式候选，不采集聊天、不调用真实回答服务。
