## 已证实的修复

- 问题编号跨轮次复用：新问题不再继承旧草稿或已关闭状态，过时结束事件不能关闭新问题。
- 回答回执：每次提交持有独立 token；重复点击、重试后的旧回执、取消／重置后的旧回执均不能修改新问题。发送前也检查原请求仍有效。
- 草稿保留：打开超过 512 张其他卡时，不再驱逐仍有草稿、选择或在途回答的记录。
- 来源身份：不同 Agent 的同一会话编号与调用编号各自独立；Claude hook 与 transcript 仍合并同一个任务。内部路由标识不进入外部深链或回答，客户端原始编号保留。
- 设置：启动语言、助手选择和提醒声音统一使用控制器注入设置；原设置键与其他数据保持。
- 助手配置：合入另一聊天的安装／登录／只读检查入口；普通用户只显示自动、Codex、Claude Code。作者的千问选项由其私有配置显式开启，该文件不进入包；其他电脑遗留的内网模型自动解释配置降为关闭，不覆盖原文件。
- 日志解析：标准 UTC 时间使用值类型解析器，保留旧格式和毫秒兼容；其他格式由持锁的旧格式解析器兼容。没有更改事件含义、文件轮询顺序或引入额外后台线程。

修前四条问题卡检查全部失败；跨来源同 ID 检查也真实失败。修后加入 10 次提交／重试／切换检查、跨来源互不关闭、reset、hook 重复、时间格式与并发解析检查。完整失败日志保留，不用最终成功覆盖。
