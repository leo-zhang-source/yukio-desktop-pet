## 行为与实现

- 两个主分类默认折叠，点击后直接列聊天，不添加项目层。已有 Deep Code 来源如有内容仍独立显示；协助助手留在自己的客户端下，以行内说明区分，不引入第三层。
- 自动刷新记录本页手动展开状态，重绘时保留焦点与滚动位置；新页面从折叠状态开始。搜索临时展开匹配分类，清空后恢复手动状态；搜索和折叠不会选择聊天或触发模型解释。
- 列表只显示能够验证原文件身份、记录哈希，并提取到可读用户内容、助手公开回复或操作的聊天。名称、事件数量、系统提醒和推理记录本身不能使空聊天显示。近期没有可读内容时再检查有限的开场记录，不误把较早有内容、近期只有记账消息的聊天隐藏。
- 每个客户端最多查看 200 个原始组、显示 20 个有可读内容的聊天；空记录不占用显示名额。页面统计和搜索同样排除明确空内容与不可读记录。原文件、数据库和证据身份不改；原文恢复后在后续刷新／来源扫描中重新出现。列表有限，不代表完整聊天历史；未能在有限窗口验证内容时暂不显示。
- Claude 已修复的桌面身份关系继续生效，同一个桌面聊天的回退记录不重复列出；不按同名合并。配置目标为 5.4（61）／工作台 0.4.13，依赖、角色素材和更新源不改。
