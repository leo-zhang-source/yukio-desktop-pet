# 阶段 4 界面复测：升级、输入与资料隔离

2026-10-30。用户确认已通过系统正常授权恢复 Yukio 测试副本和 Tart 的使用时间，并说明暂时没有 Apple Developer 账号，先继续测试。本轮继续使用源码 `8d2deb2f1752319e6cf5044d8eadd0cb8e74d8bc` 构建的 5.4 (41) 候选，没有替换现用 App，没有发布或推送，Windows 继续暂缓。

**本轮补上了本机真实窗口的升级和中文输入法证据，同时发现一项发布前必须修正的解释预览问题。独立用户安装与完整功能验收仍未完成，不能据此关闭 G4。**

## 先纠正测试工具，再重新验收

第一次恢复界面测试后，真实 5.3 (36) 副本完成了更新失败提示、取消和升级；但升级后打开工作台时，出现了作者现有历史索引。立即停止了该测试副本。检查实际进程后发现：macOS 启动 App 时保留了真实 `HOME`，虽然原生偏好使用独立目录，Python 工作台仍从真实主目录寻找资料。此前仅凭 `LSEnvironment` 声明隔离成功的结论不充分。

这是**测试工具隔离失败**，不能用第一次结果证明工作台与真实资料隔离。没有覆盖现用 App，也没有删除或迁移真实历史；已有外部记录器仍在运行。旧测试可能更新过真实记录器的状态文件，缺少事前完整数据指纹，因此不宣称真实数据目录逐字节未变。该轮没有主动点击解释发送，但当时读到了既有自动解释设置，且没有网络审计，不能仅凭“未点击”保证不存在自动请求。第一次证据单独保留，不用复测成功覆盖这个问题。

修正只进入开发测试工具：增加一个小型启动器，核对测试目录的专属标记后，把 `HOME` 设为测试目录，再启动原来的产品程序。标记缺失、不同或内容多出字节时拒绝运行；5 项边界检查通过。真实旧版程序去除签名后的代码哈希仍与公开旧包一致。测试身份、更新地址、公钥、签名和专用启动器不进入正式候选包。

随后在新目录重新生成旧版副本和测试更新包，复用同一已获授权的测试身份。分别核对升级前、升级后的实际进程环境；打开工作台后，再核对服务返回的数据库范围哈希，确认它实际使用测试历史。新测试默认关闭自动解释，没有连接作者模型配置。这个同机测试仍然不是独立环境。

## 本机升级复测结果

基线来自已保存的真实公开 5.3 (36) ZIP，目标为选定 5.4 (41) 候选的测试副本。使用临时测试密钥签名更新列表与 ZIP，保持严格签名检查；服务只监听本机，私钥生成包后删除。

| 场景 | 实际操作及结果 | 文件与资料核对 |
| --- | --- | --- |
| 更新服务中断 | 测试服务返回 503，界面提示无法取得更新信息，可取消返回 | 旧 App 文件与签名不变，预设设置和三份历史保留 |
| 暂不安装 | 界面显示 5.3 → 5.4，点击 Remind Me Later 返回设置 | 旧 App 继续运行，文件、预设设置和历史保留 |
| 下载内容损坏 | 下载时翻转 ZIP 中的一个字节，界面报告签名无法验证，拒绝安装 | 旧 App 未被替换，设置和历史保留 |
| 正常升级 | 点击 Install Update，经过解压、安装，自动重启为 5.4 (41) | 478 项测试包文件全部匹配，严格签名通过，语言、140% 大小和测试标记保留 |
| 已是测试源最新版本 | 在 5.4 中再次检查更新 | 明确提示当前已是测试源最新版本；这不代表公开更新源恢复 |
| 从只读位置运行 | 将同一测试 App 制成只读镜像，从镜像内启动并检查更新 | 明确提示需移到应用程序文件夹；只读副本、可写副本及原有 95 条历史均未受损，取消后设置仍可用 |

三份测试历史最初各 95 条，升级后逐条内容指纹相同，并已在新工作台读取。这里使用的最小历史样例起初缺少记录器所需的保存位置字段，造成测试记录器退出；已在备份这些样例后，仅补齐测试样例的字段，重新启动记录器。这不是产品数据库损坏，也不把该次退出隐去。之后三个记录器都报告正常等待，新增人工 Codex 记录被收录；原来的 95 条记录仍保留。

这证明所测成功和拒绝路径，没有覆盖更新安装到一半断电、磁盘耗尽、正式签名公证、公开服务器恢复等情况，也没有把“拒绝坏包”说成所有故障均能回退。

## 输入、设置与工作台

使用完整候选自身的问题卡，向隔离的助手目录写入明确标记的人工问题。没有向真实聊天提交测试答案。实际逐键按下 `n i h a o`，观察到带下划线的待选拼音，再按空格提交为“你好”；不是粘贴中文或直接设置文本。

完成三种检查：第一次选词后继续输入数字，得到“你好123”；切换到 Finder 菜单后返回，原草稿仍在，重新编辑得到“你好456”；正在选词时追加人工活动记录，问题卡保持“你好456ni hao”，按空格后得到“你好456你好”。这三个场景当次正常，**原来偶发无法输入的触发条件和根因仍未知**。尚未完成真实助手接收、长时间不同输入法组合及独立 Mac 的输入验收。

另观察到，文本框正在编辑时按 Escape 会清空未提交文字；本轮没有把它归因为偶发输入故障，需明确产品希望 Escape 表示取消编辑还是关闭卡片，再决定是否修改。

设置已实际从雪绪切换为千夏、从英文切换为中文、从 140% 调到 120%。两次从正常安装位置重开后，三项设置和测试标记均保留，旧的工作台进程结束，新工作台及三个记录器正常启动；中间还完成一次只读副本运行。第二次重开再次核对服务范围确属测试目录，随后经界面切回雪绪、英文和 140%。千夏实际画面可显示，演示入口可播放，人工问题结束后可出现完成牌；这不替代整套动画、多屏拖拎和全部状态的视觉验收。拖动工具返回“找不到窗口”，此项保留未验收，不记为产品拖动失败。

工作台能够显示新收录的人工聊天，从当前工作进入记录详情，并显示来源、7 条新增记录及一个成功回执；旧记录同时可查看。中文搜索通过直接设置搜索框值找到目标；自动键入／粘贴尝试没有完整写入中文，因此这里只确认过滤功能，不能据此宣称网页搜索框的所有输入方式通过。

## 新发现的问题

### P1：解释预览写错了资料接收方

在没有配置内网模型的测试资料中，实际服务返回 `provider=auto`、`destination=agent://auto`，且自动解释关闭。但“记录详情”仍显示“使用你设置的千问”；点击解释按钮后的预览进一步写着“发送到你设置的内网千问”“由这台内网模型服务器处理；当前接口没有鉴权”。实际选择的是本机助手通道，可能使用助手账号对应的服务，两者不是同一承诺。

原因已定位到 [explanation.js](../../tools/activity-workbench/dist/explanation.js) 中仍然写死的旧说明。测试停在预览并点击“暂不发送”。**发布前应按实际选择显示接收方、账号／服务方式和配置状态，同时核对当前工作、历史详情和中英文说明。** 验收需要覆盖自动选择、明确选择 Codex／Claude、用户自配内网模型以及未配置／未登录；预览必须与实际发送路径一致。当前候选未修正此问题。

### P2：旧版更新窗口有时被设置挡住

5.3 副本取消更新后再次检查，服务已返回更新列表，但最前方仍是设置窗口。关闭设置后，已有的“Software Update”窗口出现。这个现象足以解释一次“按钮似乎没反应”，不能当成所有更新失败的根因。5.4 的“已是最新版本”提示当次正常；新的可安装更新提示是否存在相同遮挡仍需复测。

## 独立 Mac 与仍未完成的验收

Tart 的系统授权已恢复。当前界面工具能看见虚拟机 Finder，但对内部文件的坐标操作反复返回“找不到窗口”，组合键也未可靠传入，因此无法完成普通用户的图形安装流程。已请用户在虚拟机里打开实际候选 DMG、复制到单独测试文件夹并反馈启动结果；没有借用命令行启动去绕过系统的应用来源检查。

候选 DMG 的既有哈希、镜像完整性与严格包内签名预检仍有效；Gatekeeper 拒绝、未正式签名公证的事实也保持不变。用户当前没有开发者账号，先继续可以完成的测试，不把缺证书等同于源码测试不能做，也不把临时签名包称为公开交付就绪。

后续仍需：从实际包完成独立安装和首次启动；测试用户自己配置助手／账号并完成真实读取与回答；验证发布前修正；补齐登录启动、多屏、完整皮肤动作、安装中断和其他失败路径。当前虚拟机已有历史测试依赖和测试用户自行登录的账号，不能称为全新安装环境。
