# GitHub 合并门槛的待执行验收

2026-11-01。目标为新仓库 `leo-zhang-source/yukio-desktop-pet`。本轮只读查询确认仓库可访问、`Remediation checks (Mac and workbench)` 工作流存在；`main` 分支保护接口返回 `Branch not protected`。因此不能沿用旧账号暂停的阻塞理由，也不能说强制门槛已经启用。

在用户明确授权本次 GitHub 写入后，按一次集中验证执行：

1. 将已审查的固定源码与文档推送到专用测试分支（不上传私有证据、原始账号状态、聊天或本机路径）；创建一份草稿测试 PR，记录精确提交。
2. 先观察同一提交的 `Mac and workbench baseline` 两遍检查；保留 GitHub 原生 run URL 和结论。
3. 在测试分支故意改错共同样例的一条预期，确认工作流红灯，不能仅以本机负控制替代。失败提交仅用于测试分支，不合入 main。
4. 配置目标主分支必须通过该检查并要求最新检查；在失败版本上观察实际 `mergeable_state`／阻止原因。不要尝试管理员绕过或强制合并。
5. 恢复正确预期，观察检查绿灯和门槛恢复。审查后再按用户当次上传范围处理 PR；只有源码和文档就绪不代表允许发布安装包。

操作可能改变仓库协作规则，所以本地记录和准备不能当作远端已经完成。没有明确上传／修改远端授权时停留在本文件和本机负控制，G2 云端部分保留待验。
