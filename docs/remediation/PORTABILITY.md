# 其他用户独立使用：依赖登记与验收边界

本阶段只登记依赖，没有把任何功能宣布为通用化完成。最终验收遵守根目录 `AGENTS.md`：优先另一台目标系统电脑或干净虚拟机，从真实发行包开始；临时 HOME、另一个工作目录、模拟接口和本机单元测试不能替代独立环境。

| 位置或能力 | 已见依赖／现状 | 需要补齐的独立用户验收 |
| --- | --- | --- |
| 安装与首次打开 | 当前包仍有临时签名、未完成正式公证的限制；5.3.3 的独立 Mac 验收记录发生系统拦截 | 实际下载保留系统隔离标记，正常安装与打开；签名、公证、包哈希和系统版本均记录，不借用开发者信任状态 |
| 三类助手活动 | 从当前用户的 Codex、Claude、Deep Code 目录读取，支持若干配置目录覆盖 | 用户自己安装并配置公开客户端；无客户端、无记录、目录变更、权限不足都有真实提示 |
| Agent 解释 | 默认使用用户自己的 Codex / Claude Code 登录；客户端版本、模型配置、可执行程序发现均影响调用 | 独立用户完成官方安装与登录、真实生成和重启；未登录、额度不足、模型不支持、路径有空格时可定位 |
| 千问／内网模型 | 已改为用户可选来源；旧适配仍需手工 `lan-model.json`，目前不支持保存鉴权密钥 | 提供可由普通用户完成的配置流程；任何服务地址和权限均来自该用户。不能依赖作者长期在线；缺少服务时基础功能可用 |
| 后台回答 | Claude 需合并自己的钩子设置；Codex 需正确本地连接；Deep Code 入口需 Node 22+、Git 和用户模型配置 | 公开步骤能自行完成；保留已有配置并可撤销；只向当前请求发送答案；真实操作由测试用户授权 |
| 网页与插件识别 | Mac 辅助功能权限、Windows UI Automation 及目标客户端可读性 | 新用户按公开说明授权；拒绝授权仍可使用独立功能；不能把实验识别能力宣称为覆盖所有服务 |
| 工作台本地服务 | 当前原生入口仍固定 8767；后台进程拥有关系尚需统一 | 旧版残留、端口占用、独立用户并存和重开；允许定位故障，不手工杀未知进程 |
| 资料与凭据 | 运行资料应留在当前用户数据目录；构建已有私有文件排除检查 | 真实安装包检查不带任何作者密钥、聊天、模型配置；升级后用户数据保留；未配置时不静默连接作者服务 |
| 资源与运行环境 | 原始素材受保护；分页、Python 运行环境和 Sparkle 来自构建；目前组合构建仍接收多个已有输入 | 建立明确输入和统一构建记录；断开作者开发目录、虚拟环境和 NAS 后，实际包仍可独立运行 |
| 开发工具与历史资料 | 本机辅助 Python 路径、NAS 备份位置和历史证据目录属于维护环境 | 公共安装流程不引用这些私人位置；开发文档用可自行安装的依赖说明；历史路径不得作为运行依赖 |
| Windows | 发布已暂停，源码与历史证据保留 | 不能恢复旧下载或打“通过”勾；恢复前须用户明确决定、Windows 实际安装包和独立 Windows 环境验收 |

每次验收至少记录：系统与架构、独立环境类型、安装包版本和 SHA-256、初始依赖、公开安装／配置步骤、所用测试账号的归属（不记录密钥）、操作结果、失败证据及未覆盖范围。真实账号登录由用户本人完成；既有离线助手协议检查不等于线上服务成功。

阶段 2 先建立这些场景的可重复记录和可自动检查部分；阶段 3 修明确的问题；阶段 4 用准备交付的实际安装包做独立用户验收。作者的 NAS 只承担私有备份作用。
