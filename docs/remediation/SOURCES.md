## 最先需要接续的主题

1. **结果归属与共同样例：**旧目录有 `CodexToolResults.swift`、`codex_results.py`、共同 fixture 和跨实现比较脚本；工作台 core 已含其中一些 Python 内容，桌宠仍保留旧失败标记。阶段 2 先验证样例是否真正覆盖已复现的串号，再在阶段 3 选择最小修复。
2. **真实回答与设置生命周期：**`local-chat-cards` 中的 `CodexAnswerTransportTests.swift` 和 `SettingsLifecycleTests.swift` 尚未进入基线。它们测试隔离接收端及旧窗口生命周期，需适配现在的工作台入口；不能把旧测试直接复制后视为真实输入已验收。
3. **工作台启动：**候选包含新 `WorkbenchRuntime.swift`、动态端口、启动状态和 launcher 检查；当前安装版也修改了同一组文件。阶段 3 要按拥有者、超时、重复打开和旧进程共存逐项接入，保留已安装的设置总览和 Agent 能力。
4. **Windows 小屏设置与审计：**小屏滚动方案确实未在当前主线的 `pet_settings.py` 中，审计分支也有独立脚本。保留到 Windows 实机整改，不恢复已暂停下载。
5. **5.3.3 与公证验收：**较新的说明修正和进行中记录独立保留。本阶段没有抢占另一条验收、替它签字或把候选覆盖桌面 App；在后续交付前必须核对最新结果与待办。

旧主目录还混有 Swift 历史记录实现、旧设置、旧打包版本和抛掷入口等变化。当前工作台已使用专用 Python core，不能把这些旧文件整体迁入来“补齐文件数”。每个保留主题都应先说明它要恢复的行为、与当前实现的差别及验收动作。
