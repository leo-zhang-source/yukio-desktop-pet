## 原因和本轮处理

| 项目 | 已核实的链路 | 本地实现及边界 |
| --- | --- | --- |
| YK-14 | 原生解析器将 Claude `Stop`／`end_turn`／`stop_hook_summary` 映射到整个任务结束，路由随后举完成牌 | 新增中性 `turn_end`，结束当前回复但不进入完成牌队列；短暂递交动作后恢复空闲，不抢走仍工作的 B 聊天。尚无可靠的 Claude 整体目标完成判定，因此普通回复结束均不举完成牌，真正完成的专门提示仍待设计和验收 |
| YK-16 | Python Claude 历史只记录内容／工具元数据，没有供工作台使用的轮次开始、结束标记 | 增加独立生命周期元数据，聊天列表与详情共用解释规则；用户请求开始、工具返回不重新开始、回复结束／中断退出、续跑恢复；迟到旧开始不覆盖较新的结束 |
| YK-15 | 本机状态文件显示 `accessAllowed=false`，虽有 `observationValid=true` 仍不能证明可识别聊天；桌面可访问性读取出现无 scheme 的 `claude.ai/epitaxy/local_…` 地址 | 只补兼容这个准确主机的地址形式，并明确设置中辅助功能权限的作用。保留准确会话 ID 映射和手动放牌；不凭标题或前台 App 清牌。缺权限的问题不能单靠此代码解决，授权后的真实切换仍待验 |

[Claude 官方 hook 说明](https://code.claude.com/docs/en/hooks)将 Stop 定义为回复结束，不能用作用户整体目标完成的证明。本轮亦接收 `PostToolUseFailure`／`StopFailure`，不自动改写用户 hook 配置。不改变其他来源既有 `task_end` 的完成语义；本轮不能扩大为所有客户端的完成判定已完善。

保留原消息和工具关联种类；新轮次标记只是安全元数据，不复制聊天正文、不重写历史、不重新采集旧库。旧 Claude assistant 的已保存 stop_reason 可作为中性结束读取。原生旧 task_start／task_abort 增加时间检查，避免已验证的迟到事件重新打开旧轮次。
