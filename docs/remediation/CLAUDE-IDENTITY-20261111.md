# Claude 桌面聊天重复：按客户端会话身份修复

2026-11-11。用户指出 58 版仍把 Claude 中一个聊天显示成多条。上轮只核对了各个 CLI 记录的身份与标题，没有打开 Claude 核对桌面聊天身份，因此“独立同名聊天”的判断不成立。上轮测试结论只覆盖其记录层检查，不能证明与客户端聊天列表一致。

## 实现

- Mac 默认读取当前系统用户的 `Library/Application Support/Claude/claude-code-sessions` 中账号／组织层级的本地会话元数据，按明确身份显示一个入口，指向当前 CLI 记录。标题优先使用桌面客户端名称，改名与回退会刷新缓存。
- 不能靠标题、路径或时间合并。跨账号／多个聊天对同一身份的冲突不用于关联；共享分叉祖先不把两个当前聊天合在一起。归档的桌面聊天不出现在最近列表。独立 CLI 聊天继续单独显示。
- 最近列表最多检查 200 个 Claude 原始组，再按会话整理。当前分支的查询使用已保存的精确会话与来源身份；旧分支晚到、采集顺序变化不能代替当前分支。当前记录尚未采集时，不在最近列表中把旧分支冒充当前聊天；原始历史不删除、不合并，不跨分支关联工具结果。
- 页面可从已知旧记录转到同一个桌面聊天的当前记录。跨分支时清空旧模型解释、撤销旧页授权并重新读取，子 Agent 或不同客户端不跟随这条关联。只是同名的聊天保持独立。
- 元数据单文件最多 2 MiB、每轮新增读取最多 64 MiB、缓存最多 512 个文件，目录扫描最多 4096 项，约 2 秒检查刷新。拒绝符号链接、未写完记录、身份与文件名不符的记录。只留身份、名称与归档状态，不保存提示词、工具设置或凭据。自定义记录根目录不借用默认桌面资料。
- 新模块加入包清单与运行指纹；最终配置 5.4（60）／工作台 0.4.12。依赖、角色素材、更新源、公钥与升级比较基线未改。
