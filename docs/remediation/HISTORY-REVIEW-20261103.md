# 历史回顾：两个独立阅读区（本机候选 41.3）

范围：在 `codex/settings-green-white` 上保留既有绿白风格、工作台主结构、目标／方法／有效性与设置页；按用户提供的 GPT 排版截图重组历史区域。沿用页面选中的解释来源，不接入新的云服务。本次只构建、验证并安装到本机，不上传 GitHub，不作公开发行或 Windows 实机通过结论。

## 使用行为

- **整体进展**：原本要做到什么、前面做到哪了、眼前在做什么、接下来要做什么。展开时可由所选解释来源生成四段通俗文字，每段还能点击现场生成更详细的解释。原始记录只放在折叠的“查看依据”中；模型不可用时显示待生成／具体错误和重试入口，不拼贴原文充当模型解读。
- **操作与交接**：短段落连续排列，下面单独列出工具与结果状态；公开进展说明、工具操作、助手交接分别标明。每项可展开生成详细解释并查看依据。翻页读取更早步骤，回到最近会取得新的快照。
- 两个区域用原生 disclosure 分别展开／折叠，可以同时打开。原有“按以前的要求回看”、历史段落详情、助手交接依据、完整记录入口继续保留。
- 重生成会创建新的解释请求，不用旧的成功缓存冒充现场生成。所有解释沿用既有页面授权、服务地址、账号与额度限制；关闭页面、停止解释或切换聊天后不能继续发起旧请求。折叠中的请求返回不覆盖当前可见内容。

## 数据边界

整体进展按明确的聊天、助手和分支身份，结合最早要求与后续公开记录；较长聊天按时间分布最多选取 160 条短片段，明确显示抽样、原文缺失和覆盖限制。模型不能据此声称已覆盖所有步骤。每次操作仍由原有配对器在同一来源／版本／轮次与无缺口的范围内配对，正文返回还需匹配操作编号；不把相邻或另一工具的返回拼在一起。

助手公开汇报不等于独立验收，工具成功不等于任务完成，收到助手回复不等于采用回复。未知计划不补写。模型输出须遵守证据范围，拒绝代码、命令、路径及较长原文照抄。内部思考不进入读取得到的公开解释材料。

## Interface Design 与 Impeccable 检查

阅读场景：返回工作时先理解目标与前后关系，再按需查看每步做法与结果。使用已确认的白色纸面与松绿色文字；新增内容以段落、较淡工具行及原生折叠组织，没有新增嵌套卡片体系。

执行 Impeccable 文件检测，并用浏览器测量、截图与键盘交互复核。检测全页报告 24 项 warning、5 项 advisory，涉及既有浅色文字、小字号及两处旧边线，不宣称全页 WCAG AA 通过；新历史段落没有加入这些旧样式。新正文、工具行、详情入口在白底上的对比度分别为 9.22:1、5.86:1、6.52:1。
