# Claude 当前进展与完成状态修复

2026-11-13；Mac 5.4 Preview 4（66）候选，工作台 0.4.17。本次用户明确要求修复、使用虚拟机检查、整理上传 GitHub，并更新桌面 App。上传目标为 `leo-zhang-source/yukio-desktop-pet` 的维护分支和 main，公开包保持预览版。

## 已确认的问题

- 独立 VM 的 Claude Code 2.1.318 普通交互结束写入 `system/turn_duration`，非交互结束写入关联答案的 `last-prompt/leafUuid`；两者没有 65 版所要求的 `stop_hook_summary`。旧版实际失败见 [65 版记录](INDEPENDENT-BUILD65-20261111.md)。
- 桌面 Claude 的 Stop 注册表可保留先前请求启动的监控与预览服务。将这些服务全部归入当前请求，会让已经结束的新请求一直显示工作中。
- 工作台主说明即使已过期，仍覆盖最新本机内容；工作解读还将先前轮次的方法当作本轮策略，并受固定 30 秒缓存和模型等待阻塞。
- 元数据历史原来没有 Claude 的轮次开始/结束标记，导航状态无法反映真实结束。

## 修复边界

完成必须对应同一会话、同一答案以及明确的客户端结束记录。仅 `end_turn`、文字声称完成、子助手结束、Stop 调用本身都不构成完成。`turn_duration` 限定交互 CLI；`last-prompt` 限定非交互 CLI；桌面保持严格的 Stop 汇总核对。当前请求的后台任务、继续执行和钩子反馈仍阻止完成，较早请求的常驻服务保留自己的归属。系统后台通知延续原任务，不冒充新的用户要求。

工作台保留最新本机记录，只有相同内容版本的模型解释可以覆盖它。新内容到达时立即刷新当前解读，模型等待不阻塞本地更新；导航轮询缩短为 6 秒。旧要求和旧方法只作明确标注的背景。历史升级重读来源并保留旧代记录；检查点只存身份及状态，不写入聊天正文、工具输入输出或思考内容。

[Claude 官方 Stop 说明](https://code.claude.com/docs/en/hooks#stop)说明 Stop 可阻止继续结束，且存在后台任务注册表；内部转录字段仍可能随客户端变化。兼容结论以本轮实际客户端与包为准。
