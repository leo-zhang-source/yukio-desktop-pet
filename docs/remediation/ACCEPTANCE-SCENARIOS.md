# 阶段 2：原有功能的检查步骤

2026-10-29，范围：Mac 与工作台。Windows 所有整改、构建及验收按用户要求暂缓；已有源码、资料、包及下载暂停状态保留。本表承接阶段 1 的功能清单。

## 三种证据要分别记录

**自动检查**使用人工记录、隔离设置、测试进程和自有接收端，适合重复发现逻辑问题。**本机交互检查**需要实际点击窗口、输入中文、观察画面。**独立用户验收**需要另一台 Mac 或干净虚拟机，从准备分发的包安装，依照公开流程配置自己的客户端和账号；不能借用作者登录、钥匙串、开发目录、私人服务或 NAS。前两种不能替代第三种。

每次使用新的输出目录；自动报告只含人工测试材料。人工失败记录必须写场景编号、源码／包版本与哈希、系统、操作、预期、实际和日志／截图。真实聊天中的测试答案由用户自行操作。没有执行过的场景保持“待验”。

## 本阶段退出条件

1. 同一源码和测试指纹连续运行两遍，Swift、Python、网页无未解释失败，数量和样例结论一致。
2. 已知偏差逐步骤登记期望值与修前值；新差异、旧失败意外消失均退出非零，不能忽略整个测试。
3. 故意改错顺序成功的断言，检查必须失败；模拟已知问题修好也必须要求更新登记。只改临时副本。
4. 测试分支在 GitHub 真正触发；错误提交失败、恢复后通过；配置必需状态检查后确认能阻止合并。单有工作流文件不满足此项。
