# 说明中的对象名称 · Mac 0.3.4

用户指出，“用户曾要求增加两个按钮”和“用户要求移除按钮”实际上涉及不同的按钮，不能只写数量。此次修改同时用于首页的内容／解释／原因、当前深入说明、历史小结与单段详细说明。

## 改了什么

- 说明先说对象名称，再讲动作。例如区分用于手动开始说明的“解释一次”和“持续解释”按钮，以及用于查看细节的“深入解释”和“之前做了什么”入口。
- 历史标题独立生成，明确对象与该段动作，不再从正文第一处逗号前截取标题；标题保留完整名称，避免名字刚好在逗号后被丢掉。
- 对已核对名称却仍只说“两个按钮”的回答进行检查。确实无法对应旧名称时说明未读到，不按当前页面倒推旧按钮名称。
- 保留普通语言的名称，同时避免将名称之间的分隔符误当作文件路径。真实路径和代码仍只留在折叠依据中。

## Technical Reasoning

共用名称表达规则接入各说明模式。ProjectContext 增加可选、600字以内的 object_names 字段，仍按明确聊天／助手／分支身份绑定；它只是供应的名称对照，不是客户端观察或执行证明。首页与深入说明携带这个单独标注的依据；历史每页共用同一份有界名称对照。遇到“这两个按钮”之类的指代，保留上一段助手的公开答复作为衔接依据，而不只保留上一段提问；当前段保留首次公开说明和最新汇报。衔接材料单独标注，不当作本段动作。各段不能借名称对照证明增删结果。

历史总结的结构化输出增加独立 title 字段，最长44字。历史标题单独检查具体名称；首页三段与深入说明以整张卡片检查首次命名，后文可以简称，避免每句话重复全名。引用及首页的结果与状态约束继续保留。验证能拒绝已知的缺名称表达，不能证明模型对每个代词或动作的语义判断都正确，因此仍保留原文依据和未知。

生成标题带来的额外输出包含在每次最多1000 tokens内，所有模式继续共享原有每小时次数、最短间隔和互斥限制。没有更换模型、接收位置或扩大到完整聊天发送。

## Beginner-Friendly Explanation

两次都说“两个按钮”，会让人误以为刚加好又删掉了。现在要说明：之前取消的是手动开始说明的按钮，后来增加的是查看细节和回顾的入口。它们用途不同，名称也不同。其他页面、功能或图片也优先使用已有的普通名称，不用“那个东西”含糊带过。
