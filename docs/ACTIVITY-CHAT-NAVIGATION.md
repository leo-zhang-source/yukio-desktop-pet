# 聊天侧栏与分类设置（本机 Mac）

桌面 Yukio 0.4.6 (27.3 本机排版版) 内置活动工作台 0.3.5 (24)。右键雪绪打开工作台，点窗口外部收起；设置仍在顶部右侧。此次交付本机 App 与桌面压缩包，没有发布 GitHub。Windows 继续由用户指定为之后可选。

## 怎么用

- **最近聊天**：按最近观察到的活动找聊天。
- **正在工作**：只看有近期开始记录的聊天，或有明确待处理请求的聊天。
- **未在工作**：只看本轮已明确结束或取消的聊天；这不代表整个项目已经完成。
- **项目**：点项目名称展开其中的聊天。优先使用客户端登记的项目，否则使用已确认工作目录的名称；不知道项目时仍能在最近聊天里找到。
- **搜索**：输入聊天名、项目名或客户端名称，再点结果。搜索与筛选只整理本机列表，不会自动换聊天或把列表发给千问。

没有足够依据时显示“状态待确认”，仍留在最近聊天。较窄窗口点击“选择聊天”打开侧栏，点击空白处或按 Escape 收起。当前选中的聊天会保留高亮，展开的项目在刷新时保持展开。辅助助手默认折叠，避免混入日常主聊天。原来的大下拉菜单不再展示。

设置分为三组：**外观与显示**（换装、大小、闲时隐藏、气泡、放下举牌）、**聊天与提醒**（跟随活动、客户端、桌宠跟随的聊天、提醒与回答）、**更多设置**（语言、登录启动、检查更新和退出）。原控件、回调与偏好保持复用；设置语言沿用用户原来选择。工作台选择“查看哪段聊天”，设置中的“桌宠跟随聊天”决定桌宠跟随对象，两者用途不同。

## 为什么这样实现

原列表为每一段聊天都重新拼出完整工作说明，真实记录量增加后一次列表读取曾需约 18 秒。新列表只读名称、项目、近期时间和轮次状态；打开具体聊天时才读取说明依据。安装后一次 27 段聊天的本机读取约 0.29 秒；这是此次样本，不是所有机器的性能保证。

项目只负责组织入口，不合并聊天和操作结果。名称相同的不同目录保留不同身份；客户端的项目映射必须通过同一聊天和源文件验证。近期有消息不等于仍在工作；明确开始记录、结束记录、来源可用性和记录器状态共同决定分类。列表约每 30 秒刷新，说明片段不完整时不能覆盖更完整的列表状态。

简而言之：先快速列出“有哪些聊天、放在哪个项目、最近是什么状态”，再按你选中的聊天解释。这样找聊天更快，也不会把同名项目或缺失记录误当成确定事实。

## 工程记录

**Implemented：**项目侧栏、名称与项目搜索、最近／正在工作／未在工作筛选、辅助助手折叠、窄窗口抽屉、列表刷新保留展开和焦点、三组原生设置；聊天目录读取与完整说明分开。过滤旧记录中直接作为名称的命令与路径，未获得名称时保留“未命名聊天”。只读查询仍受时间和数量限制，不向客户端写入项目数据。

**Verified：**217 项工作台 Python 检查、22 项页面行为检查、当前开发目录 228 项 Swift 检查、实际桌面基础源码 224 项 Swift 检查通过。Mac 独立包在移除 PATH 中 Python 的环境运行，中文及空格路径、模拟记录采集、重启接续、任务与交接小结、退出清理及包内 47 项文件哈希通过。集成包 7 项原生窗口生命周期检查和 13 段动画资源检查通过，原有 275 项资源保留。实际桌面 App 的搜索、项目、状态分类与三组设置已进行页面／窗口检查。具体安装文件、哈希与旧记录保留结果见本轮 artifacts 中的 installation.json。

**Unverified：**Windows 本轮接入与实机、新版长期运行、多种 Mac、正式签名公证、广泛解释质量和最终易读性未由本轮验证。本轮改变排版和聊天入口，不将其等同于所有模型说明准确。

**Issues：**每个客户端最多列出 20 段聊天，总量上限 60；达到数量或读取限制时显示范围提示。Claude 没有已验证的客户端项目列表时按已确认目录分组；来源未知时不猜项目。不同客户端中的同一目录不自动合并。超时或失去来源会保留未知状态。

**Next Steps：**按实际使用反馈调整聊天名称与阅读密度；更多系统和 Windows 仍为可选。发布 GitHub 是另外的交付动作，本轮没有执行。

构建与检查记录：`artifacts/activity-chat-navigation-20261025-r1/`。实际原生源码快照在其中的 `player/`，以此前桌面版源码构建，避免用当前开发目录的旧播放器覆盖现有换装和更新功能。原 App、记录数据库和配置均留本机备份，备份不进入安装包。
